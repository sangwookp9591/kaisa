## 1. Process architecture
- **Electron main** (`X/main/index.js`) + renderer (69MB) + `out/mobile-web` (10MB browser client). Package: node-pty, @xterm/headless + addon-serialize, ssh2, ws, tweetnacl, zod, @anthropic-ai/claude-agent-sdk, sherpa-onnx (speech), posthog [FILE: X/../package.json].
- **Three distinct server-ish things** [FILE]:
  1. *Terminal-host daemon* (`C/../daemon-entry.js`, bundled copy 1.1MB in `orcad-template/`): owns PTYs so they survive app restarts. Endpoint `daemon-v53.sock` (win32: `\\?\pipe\orca-terminal-host-v53-<sha256(dir)[:12]>`), `daemon-v53.token`, `daemon-v53.pid`, token/pid written mode 0600 with `wx` (`C/terminal-shell-lifecycle-scanner-wl0GErtq.js`, fns zm/Bm/Vm/Wm). Protocol version 53; `attachableDaemonProtocolVersions` lists 1..53, so a new app can attach to an old daemon (`Resources/orca-local-build.json`, `orcad-template/orcad-template.json`). Respawn is throttled (`respawnThrottle`).
  2. *Runtime RPC* in the app: `orca-runtime.json` in userData holds pid, runtimeId, `authToken`, `transports[]` (unix `o-<pid>-<id>.sock` / win named pipe `\\.\pipe\orca-<pid>-<id>`); stale sockets of dead pids are reaped (`C/runtime-rpc-socket-metadata-D3EmvY6F.js`). The `orca` CLI reads this file, connects, writes ONE newline-delimited JSON request `{id, authToken, method, params, orchestrationCapability, orchestrationContractVersion, orchestrationRequestId, expectedRuntimeSource}`, reads NDJSON until a matching `id`; `_keepalive` frames refresh the timeout; the response must carry the same `_meta.runtimeId` or the CLI aborts (`Cli/runtime/transport.js`, `client.js`, `metadata.js`). Default timeout 60s; long polls get +10s grace.
  3. *orcad* = headless Node server (same runtime, no Electron) for `orca serve`, Linux/WSL/SSH hosts. Launched by CLI with `ELECTRON_RUN_AS_NODE=1` for runtime selection, then a pinned Node downloaded on first run (10-min selection timeout); supervised with update handoff/restart brake/systemd unit (`Cli/runtime/serve-orcad-launch.js`, `serve-supervised-*.js`, `serve-service-unit.js`). Idle-exit, stale-lock reclaim, terminal census, decommission/migration modules in `Sh/orcad-*.js`. Packaged macOS serve stays on Electron because orcad has no updater.
- **Remote clients**: WebSocket transport with NaCl-box/E2EE v2 (HKDF-SHA256 key schedule, transcript-bound hello/ready with nonces, `e2ee_hello`/`e2ee_ready`), pairing via `orca://pair?code=<base64url JSON>`; offer v2 has endpoint, deviceToken, pinned Curve25519 publicKey, scope mobile|runtime, optional relay (director/cell HTTPS origins, 10-min invite token) (`Sh/pairing.js`, `mobile-relay-pairing-offer.js`, `mobile-e2ee-v2-contract.js`, `e2ee-crypto.js`). Peer desktops sharing one orcad register with `host.declareClient`/`host.peerDesktops` (`Sh/orcad-peer-desktops-contract.js`).
- **Agent-hook listener**: loopback HTTP listener; agents get `endpoint.env|cmd` with `ORCA_AGENT_HOOK_PORT/TOKEN/ENV/VERSION`; 5s slowloris cap; shell-written JSONL spool fallback (max 1024 files, 7 days) replayed on start (`Sh/agent-hook-endpoint-file.js`, `agent-hook-spool.js`, `agent-hook-listener/listener-limits.js`).
- **Auxiliary processes/threads** (why each exists) [FILE]: `session-scanner-service-entry` (child process with IPC `init|session|sessionSearch|invalidate|cancel|shutdown`; indexes provider transcripts ~/.claude/projects, ~/.codex/sessions, OpenCode sqlite into FTS5/bm25 `session-search.sqlite` + `session-parse-cache.sqlite`; keeps heavy parsing off main); `foreign-sqlite-reader-entry` (worker_threads, reads other apps' DBs); `profile-state-writer/backup-worker` (worker thread, sole SQLite writer); `usage-scan-worker` (token/cost from transcripts); `workspace-space-scan-worker`; `port-scan-command-worker`; `worker-thread-child-process-entry` (spawns children from a worker with 256KB stdout backpressure via pause/resume); `main-thread-hang-watchdog-entry` (worker; main posts heartbeats, writes a hang marker file when silent past timeout, records self-recovery); `parcel-watcher-process-entry` (fs watching isolated); `claude-profile-setup-worker`; `stt-worker` (sherpa-onnx); `computer-sidecar` (see 5); `browser-extension-native-host-supervisor`; `plugin-host-entry`.

## 3. Orchestration model (the most valuable part)
- Concepts: **Run** (durable namespace + coordinator inbox, not a scheduler), **Task** (work; status pending|ready|dispatched|completed|failed|blocked, deps JSON), **Dispatch** (one authoritative attempt; status pending|dispatched|completed|failed|circuit_broken; fields consumer_generation, depth, launch_token_hash, capability_hash, process_incarnation, host_scope, last_heartbeat_at), **Decision gate** (pending|resolved|timeout, options JSON), **Delivery** (outstanding|acknowledged|fenced).
- Schema in node:sqlite `DatabaseSync` (not better-sqlite3), `PRAGMA user_version = 43`, per-version migration functions in one transaction (`C/orcad-migration-source-retention-YqU6zjTf.js`). Tables: runs, messages (types status|dispatch|worker_done|merge_ready|escalation|handoff|decision_gate|question|heartbeat; priority; AUTOINCREMENT sequence = FIFO), deliveries (+view `outstanding_deliveries`, trigger allowing one outstanding delivery per mailbox), question_threads, tasks, dispatch_contexts, decision_gates, coordinator_runs, run_coordinator_handles, worker_dispatches, worker_terminal_resources (ownership owned|transferred|user_owned|external|released), worker_terminal_archives (transcript_pin|terminal_tail|structured_journal), mutation_receipts (idempotency key = caller_fingerprint+request_id+payload_hash), attempt_observation_facts (append-only evidence per dispatch with authority clock), removed_orchestration_work (tombstones), federated_dispatches, remote_dispatch_attachments, federation_relay_items (direction to_home|to_worker, per-dispatch sequence, acked_at), remote_questions. Also `profile-state.db` (profile_state_documents, journal_*; separate writer worker, recovery/quarantine modules in `U/main/persistence/profile-state`) and agent_session_* tables for structured sessions.
- Message delivery: send = durable enqueue (wake is best-effort). `check` returns oldest FIFO Delivery for the Run and replays it until `check --ack <delivery_id>` (ack returns next batch). Consumer generation bump fences old deliveries. Mutations carry `orchestrationRequestId`; CLI emits a recovery command on ambiguous failure (`Sh/orchestration-rpc-contract.js`, `Cli/orchestration-mutation-recovery.js`).
- Worker-start pipeline (`recordWorkerStage`): accepted -> worktree_creating -> worktree_created -> terminal_creating -> terminal_readying -> [setup_start] -> input_accepted (preamble) -> ready; remote: remote_attach_requested -> remote_input_accepted. Failure keeps `failedStage`+`residualResources`; unknown outcomes become `start_unknown`/`stop_unknown` and are never auto-retried. Readiness timeout 60s, +30s prompt-effect, +20s client grace (`Sh/orchestration-timing-budgets.js`). Worktrees are created via `createManagedWorktree` with lineage (parent worktree, caller terminal). Nesting `depth` limit is enforced.
- Heartbeat default 5 min (1-60 configurable), stale warning after 2 missed (`Sh/orchestration-heartbeat.js`).
- Federation: home runtime keeps `federated_dispatches`; the execution host keeps `remote_dispatch_attachments`; messages relay via sequence-numbered items with ack both ways; peer fingerprint + protocol_version + runtime_epoch stored per dispatch; capability must be advertised before using new opcodes ("old decoders may silently drop unknown opcodes").

## 6. Performance and weaknesses
- Choices: heavy parsing/IO in child processes and worker threads, bounded queues (256KB), caches with TTL (process table 1.5s), idle-exit for orcad, SQLite WAL + single writer worker, hang watchdog, spool+replay for hook loss, mutation receipts for exactly-once-ish writes.
- Weaknesses: install ~54MB orcad-template (nine native target dirs) + 69MB renderer + 14MB shared (1927 files) + 5.5MB main bundle; 45 DB versions and 53 daemon protocol versions of compatibility surface; app.asar is mostly unpacked (so no real asar protection). Fuses [REA ev_1932d80f]: RunAsNode, EnableNodeOptionsEnvironmentVariable, EnableNodeCliInspectArguments, GrantFileProtocolExtraPrivileges enabled; EmbeddedAsarIntegrity, OnlyLoadAppFromAsar, CookieEncryption disabled. Auth tokens sit in plaintext 0600 files (runtime json, daemon token). Orca itself depends on RunAsNode to launch orcad.

## 7. Design lessons for Kaisa
1. **Adopt** the Run/Task/Dispatch split: Dispatch = one attempt with fencing (`consumer_generation`), authority from the active Dispatch only.
2. **Adopt** durable mailbox with FIFO Delivery + explicit ack + replay; one outstanding delivery enforced in the DB.
3. **Adopt** idempotent mutations (request id + payload hash receipts) and CLI-printed recovery commands on ambiguity.
4. **Adopt** tri-state outcomes (`*_unknown`, live/unverifiable/exited); only positive proof permits kill/retry; track residual resources per stage.
5. **Adopt** PTY daemon separate from UI with versioned socket + attachable-version range + 0600 token; in Rust use `portable-pty` (ConPTY) and `vt100`/`alacritty_terminal` for snapshots.
6. **Adopt** instruction-injected worker preamble containing exact commands/IDs, plus agent hooks into a loopback listener with file-spool fallback.
7. **Adopt** data-driven agent table (detect cmd, prompt injection mode, model/effort/permission flag mappers, paste-ready signal) rather than per-agent code.
8. **Adopt** stage-recorded worker-start pipeline persisted before side effects.
9. **Adopt** capability advertisement for protocol additions; E2EE pairing with pinned key and short-lived invite for remote peers.
10. **Avoid** mixing three server roles that share code; give Kaisa one daemon with one protocol and optional transports.
11. **Avoid** heuristic liveness from OSC titles/spinner regexes as primary signal; prefer hooks + process tree, keep heuristics as fallback.
12. **Avoid** plaintext token + RunAsNode-style escape hatches; use OS keychain/peer-credential checks on unix sockets, single static binary (no pinned Node download, no 54MB per-target template).
13. **Avoid** unbounded schema migration history; ship a single schema version with forward-only migrations and tombstone tables only where audit needs them.
