## 1. Runtime topology
- **Launcher** [REA+READ]: `app.asar` is only 2.3 MB (11 `electron/*.cjs` files). REA: 2 BrowserWindows, 1 preload, 1 contextBridge API, 31 exposed members, 34 IPC ops / 13 literal channels / 0 dynamic, 0 utility processes, 0 native addons.
- **Server spawn** [REA partial + READ]: REA sees `spawn`, `SIGTERM`→3000 ms→`SIGKILL`, 200 ms HTTP readiness poll, but marks argv/env/stdio "dynamic/unresolved" — details are from reading `main.cjs`: `spawn(process.execPath, [server.js], env{…process.env, ELECTRON_RUN_AS_NODE=1, NODE_ENV=production, PORT=<freePort(0)>, HOSTNAME=127.0.0.1, LH_DATA_DIR, LH_AUTH_FILE, LH_DESKTOP_SERVER=1, LH_DESKTOP_API_SECRET=<32B random hex>}, stdio [ignore,pipe,pipe,ipc])`. Server = the Electron binary in Node mode (bundled Node 24) running Next 16 standalone from `Resources/server/standalone`. macOS adds a title-guard `--require` so the child is not registered as a GUI app.
- **Second helper** [READ]: for demo rendering the server spawns the same binary with `--browser-service` (hidden window, CDP port, dies on parent IPC disconnect; system Chrome fallback).
- **Capability header** [REA: `webRequest` + `/api` endpoints; READ]: main hooks `onBeforeSendHeaders` and adds `x-learnharness-desktop: <secret>` only to `/api/*` requests from the trusted window's main frame at the exact origin. `proxy.ts` returns 403 on any `/api/*` lacking it (timingSafeEqual).
- **Window security** [REA: explicit webPreferences; READ]: `contextIsolation:true, sandbox:true, nodeIntegration:false`, preload only; deny-by-default permissions (3 allowed, own origin only); `will-navigate` pinned to origin, `window.open` denied → `shell.openExternal`; single-instance lock.
- **Preload API** (`window.lh`) [REA 31 members, READ]: `platform`, `getPathForFile`, `chatgpt.{status,login,cancel,select,disconnect,logout,consent,onChange}`, `subscriptions.{status,login,cancel,respond,open,retry,disconnect,consent,onChange}`, `expandWindow`, `onZoom/getZoom`, `onUpdateStatus/installUpdate/getUpdateState/checkForUpdates`, `onOpenSettings`. Credentials never reach the renderer.
- **13 IPC channels** [REA]: `lh:chatgpt:control` (invoke; login/status/consent), `lh:subscriptions:control` (invoke; Copilot/xAI OAuth), `lh:subscriptions:web-browser` (dev only), `lh:chatgpt:changed` and `lh:subscriptions:changed` (main→renderer nudges, no payload), `lh:update:get`, `lh:update:check`, `lh:update-install`, `lh:update-status` (push `{status,version,revision}`), `lh:zoom`, `lh:zoom:get`, `lh:expand-window`, `lh:open-settings`.
- **Sender validation** [READ; REA saw 1 observation]: `trustedSender` = window in trusted set AND `senderFrame===mainFrame` AND exact origin. Applied to chatgpt/subscriptions/update:get/update:check; **not** applied to `zoom:get`, `expand-window`, `update-install`.
- **Private main↔server channel** [READ]: Node IPC (`child.send`, channel `lh:chatgpt`/subscriptions) lets the server request OAuth token *leases* (epoch/revision-stamped; stale leases rejected) — tokens live only in main; the server holds short leases.
- **Updates** [REA: electron-updater present; READ]: `app-update.yml` = GitHub releases (draft); autoDownload, check at start + every 24 h, `autoInstallOnAppQuit`, user toggle read from `settings.json` (`general.autoUpdate`); `installUpdate` kills the server *first* (server lives inside the bundle being swapped). Env `LH_UPDATE_FEED` can override the feed in packaged builds.
- **Fuses** [REA ev_0b23b0eb]: RunAsNode **on**, NodeOptions env **on**, CLI inspect **on**, ASAR integrity **off**, OnlyLoadAppFromAsar **off**, cookie encryption off, GrantFileProtocolExtraPrivileges on. RunAsNode is load-bearing for the design but is also a local "run arbitrary JS with a signed binary" primitive.

## 2. Harness engine as shipped
- **Bundle vs source** [REA + READ]: REA `compare-source-to-bundle` (shell): 10 files unchanged by exact digest, 0 modified, 0 removed, 1 unknown (ev_2dab23a1). Server: first-party `src/ app/ components/ lib/ docs/ scripts/ skills/ config.ts proxy.ts` ship as **uncompiled TypeScript** and `diff -r` is byte-identical to upstream HEAD (`dc4c398`, "prepare 0.4.0"); only extra file is `server-title-guard.cjs`. Compiled `.next/server` chunks grep-confirmed to contain the source literals (CLI flags, `__lh*` globals, header name, `claudecode/toolUseId`). **[UNK]** REA semantic analysis of the four 1.9 MB Turbopack chunks (and two 1.7 MB SSR chunks) did not finish (killed after ~10 min), so compiled-vs-source behavioral equivalence is not REA-verified.
- **claude CLI provider** [READ=source, literals grep-confirmed in bundle]: `claude -p --input-format stream-json --output-format stream-json --verbose --include-partial-messages --model M --effort E --system-prompt-file F --tools "" --strict-mcp-config --mcp-config F --setting-sources user --settings {"disableAllHooks":true} --disable-slash-commands --no-session-persistence --permission-prompts none --allowedTools mcp__learnharness__*`. The CLI has **zero built-in tools**: it is a pure model transport; all tools are the harness's, exposed over MCP. cwd and prompt/mcp files are per-turn temp dirs (0600), removed afterwards. The CLI owns auth/billing.
- **Loopback MCP bridge** [READ]: per-turn Streamable-HTTP MCP server on `127.0.0.1:0`, 32-byte random Bearer (timingSafeEqual → else 401), rejects calls lacking a unique `claudecode/toolUseId` or naming undeclared tools; pending calls are resolved by the harness; abort/close settle everything with error results. A live CLI process is **reused across tool round-trips** (matched by session id + tool-call ids + config/env) with 10-min idle kill, else fresh process with transcript replay.
- **Jobs / steer queue** [READ]: per-chat serialized registry on `globalThis`. Steer id is deterministic (`steer_<jobId>`); "delivered" = id present in the persisted record, so duplicates/crashes are skipped (at-least-once attempts + idempotent id → effectively exactly-once in the record). Two vehicles: live agent's steering queue at turn boundaries, or an idle wake turn (409 backoff 0.5-5 s); undelivered markers return to pending. Delivery state is independent of worker status. Recovery is **lazy** (off the `/api/jobs` poll, 30 s throttle, liveness-gated: re-deliver or re-spawn orphans).
- **Turn persistence** [READ]: write-ahead persist of input appends before the model runs; 409 per-chat single-turn guard; in-memory liveness (30-min TTL) and running-turn registry (SSE reattach, remote abort); dangling tool calls get synthesized interrupted results when rebuilding model messages.
- **Background LLM semaphore** [READ + bundle grep]: process-wide 3 permits, FIFO, abort-aware dead tickets, explicit fresh-take vs handed-off-permit accounting. Only extraction holds it now.
- **Cost metering** [READ]: usage tokens (incl. 1h cache-write split) stored per turn/job; dollars derived at read time via the model catalog, never stored; unpriced models counted separately (never silent zero); subscription providers excluded from API dollars. No budget cap/enforcement found [UNK elsewhere].

## 4. Footprint & weaknesses [direct measurement of files; runtime RSS not measured]
- 439 MB app: Electron Framework 238 MB, `Resources/server` 173 MB (node_modules 112 MB/92 pkgs: @napi-rs 27, @img 18, pdfjs 17, next 17, @streamdown 10; `.next` 50 MB, shipped tests/docs 5.5 MB), asar 2.3 MB.
- Processes: Chromium main/GPU/renderer/network + a **full second Electron binary** as the server + optional third (`--browser-service`) + one `claude` child per active turn.
- First-party engine is duplicated across four ~1.9 MB route chunks → forces `globalThis` singletons (wake registry, semaphore, turn registry).
- Weaknesses: plaintext credentials; RunAsNode/NodeOptions fuses; full `process.env` forwarded to server; unauthenticated page routes; non-atomic chat/job writes; memory-only liveness, lazy recovery; `LH_UPDATE_FEED` override; inconsistent sender checks.

## 5. Lessons for Kaisa (ideas only)
1. **Adopt**: model CLI as dumb transport (no built-in tools/hooks/persistence); serve tools yourself over a per-turn loopback MCP endpoint with random bearer and tool-use-id dedupe.
2. **Adopt**: deterministic job/steer ids + "delivered iff present in the durable log" for idempotent effect; keep delivery state separate from worker state.
3. **Adopt**: write-ahead persist of input, one turn per session, synthesized "interrupted" results for dangling tool calls.
4. **Adopt**: append-only JSONL evidence, derived views, delta-shaped settings (absent = default), per-family format stamp, one writer per store.
5. **Adopt**: one global FIFO background-LLM permit pool with abort-aware tickets; tokens stored, dollars derived at read time, "unpriced" as a first-class state.
6. **Adopt**: credentials stay in the privileged process; workers get short epoch-stamped leases over private IPC.
7. **Avoid**: a second full Electron/Node runtime as backend and browser helper; in Rust use one supervisor plus sidecars and no RunAsNode-style fuses.
8. **Avoid**: plaintext credential files (use the OS keychain); write all JSON state tmp+fsync+rename.
9. **Avoid**: poll-triggered lazy crash recovery and memory-only liveness; run an explicit boot-time recovery pass over the durable log.
10. **Avoid**: forwarding the whole parent env to children, env test seams in release builds, and uneven per-channel sender checks.
