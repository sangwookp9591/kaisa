## Tasks

### T01 ☑ Test conventions applied to existing code
- **Requirement.** NFR-06, FR-02, FR-03.
- **Change.** Rename the existing tests to condition-and-expectation sentences. Replace magic numbers with named constants,
  for example `EXIT_SUCCESS` and `MAX_SUFFIX_LEN`. Build ID text through domain helpers.
- **Acceptance.** Every test in the workspace satisfies the three rules, and CI is green.

### T02 ☐ Domain: event envelope and sequence
- **Requirement.** FR-04 (part).
- **Change.**
  - `Sequence` newtype with `FIRST` and `next()`.
  - `EventKind` enum (`#[non_exhaustive]`).
  - `Event { sequence, kind, subject, payload_version }`.
  - The canonical byte encoding used for hashing. It must be deterministic and independent of field order.
- **Tests.**
  - `the_first_sequence_is_followed_by_the_second_sequence`
  - `the_canonical_bytes_of_an_event_are_the_same_on_every_call`
  - `events_that_differ_only_in_subject_have_different_canonical_bytes`

### T03 ☐ Domain: attempt state axes and legal transitions
- **Requirement.** FR-05.
- **Change.**
  - Four axes: `Execution`, `Outcome`, `Verification`, `Cleanup` (architecture §5.1).
  - A transition function that returns `Result<_, IllegalTransition>`.
  - `Unknown` can never move to a new start.
- **Tests.**
  - `an_admitted_attempt_can_start_running`
  - `an_exited_attempt_cannot_start_running_again`
  - `an_attempt_in_unknown_state_cannot_be_restarted_without_proof`
  - `a_zero_exit_completes_the_outcome_but_leaves_verification_not_started`
  - `cleanup_cannot_reclaim_before_preservation_has_a_receipt`

### T04 ☐ Ledger: hash chain (pure)
- **Requirement.** FR-04.
- **Change.**
  - `ChainHash` (blake3) computed as `hash(prev_hash ‖ canonical_bytes)`.
  - `GENESIS` constant.
  - `verify_chain()` returns the first broken sequence.
- **Tests.**
  - `a_chain_built_from_recorded_events_verifies_cleanly`
  - `editing_a_recorded_event_breaks_the_chain_at_that_event`
  - `removing_an_event_from_the_middle_breaks_the_chain_at_the_following_event`
  - `an_empty_chain_verifies_cleanly`

### T05 ☐ Ledger: SQLite event store with a single writer
- **Requirement.** FR-04.
- **Change.**
  - `EventStore::open(path)` with WAL and `synchronous=FULL`.
  - `append()` assigns the sequence and chain hash in one transaction.
  - `read_from(sequence)`.
  - Exclusive writer ownership: `EventStore` is the writer and readers are separate.
- **Tests.**
  - `appending_events_assigns_consecutive_sequences_starting_at_first`
  - `events_survive_closing_and_reopening_the_store`
  - `a_store_whose_row_was_edited_on_disk_fails_chain_verification`
  - `reading_from_a_sequence_returns_only_that_event_and_later_ones`

### T06 ☐ Ledger: outbox
- **Requirement.** FR-06.
- **Change.**
  - `record_intent(effect, event)` is atomic.
  - `pending_intents()`.
  - `complete(intent, receipt)`.
  - Recovery lists the intents still pending after a reopen.
- **Tests.**
  - `recording_an_intent_also_records_its_event_in_the_same_commit`
  - `a_completed_intent_is_no_longer_pending`
  - `intents_left_pending_before_a_crash_are_listed_after_reopening`
  - `completing_an_intent_twice_with_a_different_receipt_is_rejected`

### T07 ☐ Protocol: NDJSON framing and hello
- **Requirement.** FR-07.
- **Change.**
  - `FrameReader` / `FrameWriter` over `BufRead` / `Write` with a maximum frame size.
  - `Hello { protocol_version, capabilities }`.
  - Negotiation keeps the intersection of capabilities.
- **Tests.**
  - `a_written_hello_is_read_back_unchanged`
  - `a_frame_larger_than_the_limit_is_rejected_without_reading_it_all`
  - `a_partial_frame_at_end_of_stream_is_reported_as_truncated`
  - `negotiation_keeps_only_capabilities_both_sides_advertise`

### T08 ☐ Workspace: source-state decision and preservation inventory (pure)
- **Requirement.** FR-09 (part).
- **Change.**
  - `SourceChoice` (`CommittedOnly`, `IncludeUncommitted`, `CommitFirst`).
  - Classify parsed `git status --porcelain=v2` entries into an inventory: tracked, untracked, ignored-build and ignored-user.
  - `covers()` checks whether a preservation receipt covers a deletion.
- **Tests.**
  - `a_clean_tree_needs_no_source_choice`
  - `a_dirty_tree_defaults_to_committed_only`
  - `untracked_files_are_included_in_the_preservation_inventory`
  - `a_deletion_not_covered_by_the_receipt_is_refused`

### T09 ☐ Workspace: git worktree create/remove through the git CLI
- **Requirement.** FR-09.
- **Change.**
  - `create_worktree(repo, base, branch)`.
  - `inventory(worktree)`.
  - `remove_worktree(worktree, receipt)`. It refuses to remove a worktree whose changes the receipt does not cover.
  - Integration tests run in temporary repositories.
- **Tests.**
  - `a_worktree_created_from_main_starts_at_mains_commit`
  - `removing_a_worktree_with_uncovered_changes_is_refused`
  - `removing_a_worktree_after_preservation_deletes_its_directory`

### T10 ☐ Sys / Keeper: durable exit record (std process, all OSes)
- **Requirement.** FR-08 (part).
- **Change.**
  - The keeper spawns a child process, waits for it, and writes an exit record (status, time, incarnation) with fsync.
  - The record can be read back after a restart.
- **Tests.**
  - `a_child_that_exits_successfully_leaves_a_success_exit_record`
  - `a_child_that_fails_leaves_its_failure_code_in_the_exit_record`
  - `an_exit_record_can_be_read_after_the_keeper_is_gone`
