# M1 — Verified team: task breakdown

| | |
|---|---|
| Milestone exit | Nothing reaches the user without fresh evidence; tampered candidates are never delivered; blocking review findings are fixed by bounded revision without a human in the common case; a second session needs no re-explanation; pipelines advance without an LLM; Unknown is never retried ([`architecture.md`](../architecture.md) §17) |
| Conventions | As in M0: every sub-task is its own commit, CI green on all three OSes before the next task, tests follow [`testing.md`](../testing.md) (sentence names, domain vocabulary, no unexplained numbers). |
| Status legend | ☐ todo · ◐ in progress · ☑ done |

## Dependency graph

```
T20 (plan + scheduler) ── T21 (verification loop) ── T22 (delivery gate) ──┐
T23 (repository index + impact sets) ── T24 (full context packs) ──────────┤
T25 (knowledge) ── T26 (injection log + evidence gate) ────────────────────┤
T27 (router + catalog) ── T28 (Codex observed adapter, local models) ──────┼── T31 (team run e2e)
T29 (policy snapshot + settings risk scanner) ─────────────────────────────┤
T30 (TUI) ─────────────────────────────────────────────────────────────────┘
```

The order follows the exit criteria: a team is only useful once its work is verified (T20–T22), and
verification is only trustworthy once the evidence is fresh and the candidate immutable (T21).

### T33 Light work on a registered local model (F37)

Found while checking F37 against the run path: `routed_model` routes over Claude Code's built-in catalog only, so a model added with `kaisa agent add` is never chosen. Wiring the personal catalog in alone would change nothing observable: the grader's lowest grade is T1 (developer, tester, researcher, documentation) and reviewers are T2, so no task in today's run path is light (T0) work. F37 names summaries, classification and first-pass reviews as the light work.

| Status | Sub-task | Tests |
|---|---|---|
| ☑ T33a | Decided (user, 2026-10-31): light work is a **first-pass review**. It runs only when a T0 local model is registered, before the T2 review; its blocking findings send the candidate back for revision without spending the T2 review; its approval is advisory, so the T2 review still decides | — |
| ☐ T33b | The first-pass route: the cheapest registered T0 local model; never chosen for code edits or security review (Codex) | `a_registered_local_model_takes_first_pass_review_and_never_code_edits` |
| ☐ T33c | The verified run takes an optional first-pass reviewer: blocking findings revise; approval or an unreadable verdict still goes to the T2 review | `a_first_pass_blocking_finding_revises_without_the_full_review`, `a_first_pass_approval_still_needs_the_full_review` |
| ☐ T33d | `kaisa local-agent` ends with the model's final answer, the CLI launches it as the first-pass reviewer, and the attempt line says `model: local (light work)` | `a_light_task_runs_on_the_registered_local_model` |
